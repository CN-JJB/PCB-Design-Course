# 03｜边沿速度、传播延迟与“高速”的真正含义

> 🎯 **本章目标**：不再用“时钟多少 MHz”粗暴判断高速；学会比较 **edge time（边沿时间）** 与 **interconnect flight time（互连传播时间）**。

配套互动实验：[Edge Rate Lab](../interactive/edge-rate-lab.html)

---

## 1. 一个 1 MHz 信号也可能是“高速问题”

假设两个器件都输出 1 MHz 方波：

```text
器件 A：rise time = 20 ns
器件 B：rise time = 0.5 ns
```

它们重复频率一样，但 B 的边沿变化快 40 倍。

对 PCB 互连来说，反射、串扰、EMI 等现象更关心的是：

> **电压/电流变化到底有多快。**

因此以后看到 `10 MHz SPI`、`25 MHz clock`、`1 MHz PWM`，都不能只靠频率标签判断。

先查驱动器的：

- rise time；
- fall time；
- slew rate setting；
- output drive strength。

如果手册没给，再用器件族、IBIS 模型、实测或保守工程假设建立范围。

## 2. 方波为什么不只含一个频率？

理想方波由基波和一系列高次谐波组成。

真实数字边沿不是无限快，所以高频成分会逐渐衰减。

在工程上，经常使用与上升时间相关的带宽估算。例如对于单极点响应，常见关系是：

```text
BW ≈ 0.35 / tr
```

这里 `tr` 通常按 10%→90% 上升时间定义。

例子：

```text
tr = 1 ns
BW ≈ 350 MHz
```

这不是说“这个数字信号的最高频率严格等于 350 MHz”，而是告诉你：

> 一个看起来只有几十 MHz 重复频率的数字波形，可能要求互连正确处理数百 MHz 量级的频率成分。

不同教材还会使用 `0.5/tr` 等 knee-frequency 经验表达。**这些都是建立量级直觉的近似，不是接口规范。**

## 3. PCB 上的变化不是瞬间到达另一端

电磁波在介质中的传播速度低于真空光速：

```text
v ≈ c / √ε_eff
```

- `c`：真空光速；
- `ε_eff`：有效介电常数，取决于微带/带状线结构、材料和场分布。

如果粗略把 `ε_eff` 看成 3～4 的量级，你会得到一个非常有用的直觉：

> PCB 走线上每毫米都有若干皮秒传播时间；十几厘米互连的 flight time 已经可以达到接近 1 ns 的量级。

**实际设计不要用这句量级估算代替场求解器或板厂阻抗模型。**它只用来决定“我是否应该开始考虑传播”。

## 4. 什么时候要把走线当作传输线？

不要背一个绝对长度。

比较：

```text
走线单程传播时间 td
vs.
驱动边沿时间 tr
```

如果：

```text
td << tr
```

那么走线各处的电压可以近似“几乎同时变化”，集中参数模型往往够用。

当：

```text
td 与 tr 已经是同一量级的重要分数
```

负载在边沿还没有结束前，就可能看到传播和反射过程，传输线模型开始有意义。

很多工程资料会使用 `td > tr/6`、`td > tr/10` 等作为“开始警惕”的经验边界。课程不会把其中任何一个写成自然定律，因为最终容许程度还取决于：

- 阻抗不连续程度；
- 驱动端输出阻抗；
- 负载输入结构；
- 噪声裕量；
- 拓扑；
- 允许的 overshoot / ringing；
- EMI 目标。

## 5. 一个更实用的判断流程

拿到一个网络：

### Step 1：找 `tr/tf`

优先顺序：

1. Datasheet；
2. IBIS model；
3. Hardware Design Guide；
4. 示波器实测；
5. 没有资料时做保守估计。

### Step 2：估计最长电气路径

不是只量 PCB 上直线距离，还要考虑：

- package escape；
- via；
- connector；
- cable；
- stub；
- branch。

### Step 3：比较 `td/tr`

比例越大，越需要认真处理 transmission-line effects。

### Step 4：检查是否有明显阻抗突变

例如：

- 走线宽度突变；
- plane split；
- long stub；
- test pad；
- connector；
- via transition；
- 不正确的差分 breakout。

## 6. ❌ 故障板：25 MHz 时钟为什么还会振铃？

一块 MCU 板：

```text
Clock = 25 MHz
trace = 120 mm
```

初学者：

> “才 25 MHz，不高速。”

但假设 I/O 的实际 rise time 约为 1 ns。

120 mm FR-4 互连的单程 flight time 已经可能与 1 ns 的重要分数处在同一量级。

如果负载端还是高阻输入、源端驱动很强、线路存在明显阻抗不连续，就可能看到：

- overshoot；
- undershoot；
- ringing；
- EMI 高频谐波增加。

正确的问题不是：

> “25 MHz 高不高速？”

而是：

> “这个 **1 ns 边沿** 经过 **120 mm 互连** 时，分布效应是否足够大到影响接收端？”

## 8. KiCad 里应该做什么？

KiCad 不知道你的芯片真实 rise time，因此不能仅靠 DRC 自动判断“这条网络要不要当传输线”。

你应该在设计前建立一个 **Critical Nets Table**：

| Net / Bus | Nominal Rate | Edge Time Source | Max Length | Reference | Special Rule |
|---|---:|---|---:|---|---|
| HSE_CLK | 8/25 MHz | oscillator datasheet | TBD | L2 GND | keep short |
| USB_FS | 12/480 Mb/s signaling context | USB design requirement | TBD | L2 GND | differential |
| SDIO_CK | config dependent | MCU/SD device docs | TBD | L2 GND | topology review |
| SPI_SCK | config dependent | driver datasheet/IBIS | TBD | L2 GND | source termination option |

这里的 `TBD` 不是偷懒，而是在提醒：**规则必须在有来源后再填。**
