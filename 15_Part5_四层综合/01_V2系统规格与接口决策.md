# 01｜V2 系统规格与接口决策：先冻结“要做什么”，再打开 PCB Editor

> 综合板最常见的失败，不是走线技术差，而是规格一直在漂。今天加 USB，明天加 CAN，后天又想加 SD 卡，最后原理图和布局一起失控。

Part 5 的第一步不是画线，而是冻结一个**可验证的 V2 产品定义**。

---

# 1.1 V2 的任务边界

本课程 V2 定义为：

| 模块 | 冻结选择 | 为什么 |
|---|---|---|
| MCU | STM32F407VGT6 / LQFP100 | 延续 V1；资源足够；避免 BGA 干扰四层综合训练 |
| USB | USB 2.0 Full-Speed device | 第一次完整训练差分 + ESD + connector boundary |
| USB Connector | USB-C receptacle，USB2-only | 现代实用；device-only 逻辑可控 |
| CAN | CAN 2.0B ×1 | 工业接口、保护、终端与 cable EMC 训练 |
| CAN PHY | 3.3 V transceiver | 让逻辑电源架构简单；最终料号仍需按系统故障容限选 |
| Storage | microSD / SDIO 4-bit | 并行数字、CLK、connector 与 silicon errata 训练 |
| Debug | SWD | 必须可量产、可调试 |
| UART | 1 路 test/debug header | Bring-up 非常有价值 |
| Power In | USB 5 V | 简化第一次综合板电源入口 |
| Main Rail | 3.3 V | MCU / SD / transceiver 主域 |
| PCB | 4 layers | 本 Part 的毕业目标 |

不加入：

- Ethernet；
- SDRAM；
- HDMI；
- BGA；
- RF；
- 隔离 CAN；
- USB HS external PHY。

这些不是“永远不学”，而是留给 Part 6~8。

# 1.2 为什么 USB-C 这里只做 USB2 device-only

USB-C 是**连接器系统**，不等于 USB 3.x，也不等于 USB PD。

V2 只需要：

- USB 2.0 D+ / D-；
- VBUS 5 V；
- GND；
- CC1 / CC2 作为 device/UFP attach detection；
- Shield；
- ESD protection。

不实现：

- SuperSpeed pairs；
- Power Delivery controller；
- source role；
- dual-role power；
- alternate mode。

这种范围冻结非常重要，否则你会因为“用了 Type-C”就把一个 MCU 教学板做成 USB-C/PD 课程。

> USB-IF 在 2026-04-08 发布 USB Type-C Cable and Connector Specification Release 2.5。真正生产设计时，CC 电阻值、连接器定义和 compliance 必须对照当前 USB-IF 规范，而不是只抄一张网上原理图。

# 1.3 USB 的工程问题清单

你需要提前决定：

### 电气

- STM32F407 使用哪个 USB OTG FS instance；
- DP/DM 对应 pin 是否与其他功能冲突；
- VBUS sensing 是否使用；
- device-only 下 CC1/CC2 如何实现；
- 是否预留 source-series / 0 Ω tuning pads；
- ESD array 的 working voltage / capacitance / IEC level 是否合适。

### PCB

- connector 必须在板边；
- ESD 位于 connector 与板内 logic 之间；
- D+/D- 尽量保持对称、参考连续；
- 不制造 test stub；
- Shield 的处理必须有结构理由；
- VBUS 入口要进入 power-protection/power-tree 区，而不是穿过敏感区。

### Firmware

- device enumeration；
- VBUS attach/detach；
- endpoint throughput；
- suspend/resume 如果项目需要。

# 1.4 CAN 的工程问题清单

STM32F407 提供经典 CAN controller，但 controller 不能直接接 CANH/CANL。

需要 PHY/transceiver：

```text
STM32 CAN_TX/CAN_RX
        ↓
CAN transceiver
        ↓
protection / optional CMC / termination footprint
        ↓
CAN connector
        ↓
cable
```

这里故意把它看成五个 block。

## Transceiver 选择思路

本课程以 `TCAN332` 这类 3.3 V CAN transceiver 为教学参考：

- 3.3 V supply；
- compatible with classic CAN；
- transceiver 本身支持更高能力并不意味着 STM32F407 controller 自动变成 CAN FD；
- 最终产品仍要根据 common-mode range、fault protection、ESD、temperature、standby 等系统要求选料。

TI 当前 TCAN33x datasheet 在 2025 年仍有修订版，说明“料号选择”本身也是需要重新核对的工程工作。

## 终端不要默认焊死

120 Ω 端接是否需要，取决于**这块板在总线拓扑里是不是端点**。

因此 V2 建议：

- 预留 120 Ω termination footprint；
- 通过 jumper / solder bridge / DNP 策略决定是否装；
- BOM 明确 `DNP unless endpoint`；
- 不把“CAN 板必须有 120 Ω”写成无条件规则。

## Protection

V2 至少为：

- CANH；
- CANL；
- connector-side transient path；

预留明确保护位置。

TI TIDA-00629 就是专门围绕 CAN 的 IEC ESD / EFT / surge protection 做的验证型参考设计；本课程借它学习方法，而不是照搬器件值。

# 1.5 microSD / SDIO 的工程问题清单

STM32F407 的 SDIO 支持：

- CLK；
- CMD；
- D0~D3 作为 4-bit SD bus。

RM0090 说明 SDIO adapter clock 与总线时钟关系，并说明 SD card 可使用 D0 或 D[3:0] 数据宽度。

但 V2 不能只看 Reference Manual，还必须查 **ES0182 silicon errata**。

当前 STM32F405/407 errata 对 SDIO 明确列出多项限制，包括：

- hardware flow control 可能导致错误数据；
- clock-divider bypass mode 有限制；
- NEGEDGE mode 可能导致 data corruption；
- 某些 clock relationship 下可能出现 underrun/错误传输。

这给出一个很重要的工程教训：

> **“外设在 datasheet 里存在” ≠ “所有配置都能放心用”。**

所以 V2 的 SDIO 章节同时包含 PCB constraint 和 firmware validation。

# 1.6 Power Budget：先粗算，别等板子发热才想起来

USB 提供 5 V，V2 生成 3.3 V。

在画原理图前必须建立 budget：

| Load | 状态 | 需要记录 |
|---|---|---|
| STM32F407 | worst intended workload | current estimate / measured target |
| microSD | write / initialization transient | peak + average |
| CAN transceiver | dominant/recessive + bus load | operating current |
| LEDs | all-on worst case | resistor/current |
| pull-ups | static | total |
| debug peripherals | active | current |
| margin | — | ≥设计团队定义的 margin |

不要直接写：

> “LDO 额定 600 mA，所以板子一定能用 600 mA。”

还要看：

```text
P_loss ≈ (5V - 3.3V) × I_load
```

以及：

- package thermal resistance；
- board copper；
- ambient；
- microSD transient；
- USB input limits；
- connector/contact drop。

Part 3 的 power-budget 思维在这里正式进入项目 sign-off。

# 1.7 Mechanical / Debug 规格也必须冻结

至少定义：

- 板框尺寸范围；
- USB-C 在哪一条板边；
- CAN terminal 在哪一条板边；
- microSD 是侧插还是顶插；
- SWD 是否能在装进外壳后访问；
- Reset / Boot / User key 是否需要；
- mounting hole 是否需要；
- 测试点是否允许 pogo-pin；
- 丝印需要显示哪些接口方向和 pin 1。

PCB 从来不是纯电气对象。
